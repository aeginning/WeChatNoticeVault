# 微信防撤回 2.3.0

Android 原生 Java 项目，面向 Android 8.0+（minSdk 26），JDK 17、AGP 8.7.3、Gradle 8.9、compileSdk 35。包名 `com.aeginning.noticevault`。

> 本项目通过 Android `NotificationListenerService` 读取系统实际交付给应用的通知字段。它不是微信注入/破解工具，不能读取微信私有数据库，也不能恢复未出现在系统通知中的消息、隐藏预览、图片、语音或视频。

## 本次性能改进

- **分页检索**：消息列表每页最多读取 30 条，按时间和数据库 ID 做 keyset 分页，不再把最多 10,000 条解密记录一次性装进内存。
- **复合索引**：数据库 schema v2 新增类型/时间/ID 复合索引，加速分类筛选和时间范围查询；旧数据库升级仅新增索引，不删除或重写记录。
- **按需解密**：游标按时间倒序读取，解密后仅保留当前页；搜索命中足够数量后立即停止读取。文本搜索仍需逐条解密候选记录，因为正文采用端侧加密且不在明文数据库中建立搜索索引。
- **搜索任务隔离**：搜索使用独立单线程执行器；新关键词会取消旧搜索，避免慢查询阻塞备份、清理和其他 I/O 工作。
- **有界通知队列**：通知写入线程最多缓存 256 条待处理通知；突发情况下队列满时会拒绝新的排队任务，不会无限占用内存。队列溢出会累计记录数量，并在首页状态区提示；已接收的任务在服务正常销毁时会排空队列。
- **降低对象分配**：复用加粗字体对象，避免每个列表文本控件重复创建 Typeface。
- **压缩后加密**：新消息记录会先尝试快速 GZIP 压缩，仅当压缩结果更小时才采用压缩数据，再使用 Android Keystore AES-GCM 加密。压缩标志复用密文头字节的最高位；旧版未压缩记录仍可直接解密，不需要数据库迁移。解压上限为 64 KiB，以防止异常压缩数据造成内存耗尽。
- **数据库完整性检查**：提供只读 `PRAGMA quick_check(1)` 检查，显示记录数量和数据库/WAL/SHM 占用；检查不解密每条消息，也不会自动修复或修改数据。
- **数据库整理**：数据管理页面提供显式“整理本地数据库”，在后台执行 WAL checkpoint 和 VACUUM，尝试回收删除后产生的空闲页面。整理过程可能受其他数据库连接占用影响。
- **快速筛选**：消息列表支持全部、普通消息、撤回提示、通知来源及最近 24 小时 / 7 天 / 30 天筛选，并可逐页加载更多。应用包名筛选在解密后执行，不建立明文来源索引。
- **界面主题**：支持跟随系统、浅色和深色模式；设置保存在本地偏好中，不影响通知监听及数据加密。
- **消息预览隐私**：可遮挡列表中的会话、标题和正文预览；点击记录仍可查看完整详情，关闭遮挡不会改写或删除消息。

## 功能

- **通知来源管理**：首次运行默认仅保存微信通知；可从手机启动器应用列表中选择其他通知来源，也可恢复为仅微信。
- **异步通知写入**：通知数据进入单线程 I/O 队列，复用数据库连接，不在通知回调线程直接执行 SQLite 操作。
- **撤回识别增强**：覆盖常见中英文撤回提示文案，采用完整短语匹配，降低普通聊天引用“撤回”字样造成的误判。
- **撤回候选精确关联**：仅关联同一通知来源、同一会话、撤回提示前 5 分钟内的普通消息；每条撤回最多保存 30 个候选 ID，候选扫描最多解密 500 条记录。
- **候选消息详情**：点击撤回记录可异步读取并展示仍存在的候选消息正文；候选仅是时间/会话匹配结果，不等于微信确认的实际撤回对象。
- **MessagingStyle 捕获增强**：优先读取 Android 消息样式通知中最近 8 条消息（含发送者标签），再回退到大文本、文本行和摘要，正文仍受 16 KiB 上限约束。
- **本地数据加密**：消息记录字段使用 Android Keystore 管理的 AES-256-GCM 密钥逐条加密。SQLite 中的时间戳、记录类型和行 ID 保留为索引元数据；本项目不是 SQLCipher 整库加密。
- **自动清理**：用户可选永久保留、7 天、30 天或 90 天。默认关闭自动清理；开启后约每 12 小时执行一次过期记录清理。
- **设备锁保护**：可要求使用 Android 系统设备凭据验证；应用启用 `FLAG_SECURE` 隐藏最近任务缩略图。
- **消息详情与复制二次确认**：复制前显示内容预览，并要求用户二次确认后才写入系统剪贴板。
- **收藏重要消息**：每条记录支持收藏/取消收藏，并可按“收藏”筛选；收藏标志写入现有 AES-GCM 加密载荷，旧记录默认未收藏，不增加明文数据库列。
- **多选批量删除**：长按消息进入选择模式，可选择已加载记录并按批次删除；删除前再次确认，单次最多 100 条，使用 SQLite 事务和绑定参数。
- **自动备份提醒**：可设置 1–365 天提醒周期，按最近一次成功完成的加密备份计算；提醒在应用打开时显示，不申请后台通知权限、不在后台弹系统通知。
- **加密备份/恢复**：`.nvbk` 使用 PBKDF2-HMAC-SHA256（210,000 次迭代）派生 256 位密钥，再用 AES-256-GCM 加密。新备份包含格式版本号；导入兼容旧版直接导出 JSON 数组的备份。导入采用事务合并、重复检测和撤回候选 ID 重映射。
- **数据限制**：备份文件最大 50 MiB，单个备份最多 10,000 条记录；字段长度和撤回关联数组均有上限。导出时如果本机总记录超过 10,000 条会明确失败，不会静默截断。
- **Shizuku 状态**：检测 Binder 在线和应用授权状态。Shizuku 为可选项，通知留存本身不依赖 Shizuku。

## 首次使用

1. 安装 APK 并打开应用。
2. 点击“开启通知监听权限”，在 Android 系统设置中允许“消息留存通知监听”。Shizuku 不能替代这项授权。
3. 首次默认仅保存微信通知；在“通知来源管理”中可以添加其他应用。
4. 可在“自动清理期限”设置保留周期。默认不自动删除任何记录。
5. 可启用“设备锁保护”；启用前须先设置手机系统锁屏凭据。
6. 定期导出密码加密备份。忘记备份密码无法恢复备份内容；建议使用独立、安全的密码管理器保存密码。
7. 删除大量旧记录后，可使用“整理本地数据库”回收 SQLite 空闲页面。

## 备份兼容性

- 新版导出采用 `NoticeVaultBackup` JSON 封套，包含 `version: 1`、导出时间和记录数组。
- 导入同时接受旧版本的 JSON 数组根结构，因此可导入旧版 2.1.0/2.1.2 备份。
- 导入采用数据库事务；格式校验或写入失败会回滚本次批量导入。
- 相同时间、类型、应用、会话、标题和正文均相同的记录会被跳过，避免重复恢复。
- 数据库 schema 仍为 v2，收藏功能不增加明文列或索引；新写入/更新的加密 JSON 载荷可包含可选 favorite 标记，旧载荷缺少该字段时默认 false。Keystore alias 与原有密文读取兼容性保持不变。

## 构建

需要 JDK 17、Android SDK 35 和 Gradle 8.9：

```bash
gradle --no-daemon testDebugUnitTest
gradle --no-daemon assembleDebug
```

GitHub Actions 会在 push / PR / 手动触发时执行单元测试和 Debug APK 构建，上传当前版本对应的 Debug APK、源码和测试报告 artifacts。

### 正式 Release 签名与发布

Release 签名由 .github/workflows/release.yml 负责，只在推送与 versionName 一致的 v* 标签时执行。签名文件不进入仓库，需在 GitHub 仓库 Settings → Secrets and variables → Actions 中配置以下 Repository secrets：

- RELEASE_KEYSTORE_BASE64：正式签名 JKS/PKCS12 文件的 Base64 内容。
- RELEASE_KEYSTORE_PASSWORD：keystore 密码。
- RELEASE_KEY_ALIAS：签名 key alias。
- RELEASE_KEY_PASSWORD：key 密码。

工作流会校验标签版本、解码临时 keystore、运行单元测试、构建 Release APK、验证 APK 签名、生成 SHA-256 校验文件，并创建 GitHub Release。缺少任何签名 secret 时会失败退出，不会发布未签名 APK。

**签名兼容警告：** Release 必须使用与你准备继续升级的已安装版本相同的签名证书，否则 Android 不允许覆盖安装。不要随意新建密钥替换旧发布密钥，也不要把 keystore 或密码提交到仓库。更换签名身份前，必须先在旧应用中成功导出加密备份并验证可恢复性。

## 安全边界与已知限制

- Android Keystore 记录密钥不可导出。卸载应用、清除应用数据、重置设备或 Keystore 密钥失效后，旧数据库密文可能无法解密；重要记录应定期导出密码加密备份。
- **密钥失效保护**：解密时如果 Keystore alias 缺失或不可读取，应用会停止解密并拒绝自动生成替代密钥。只有数据库确认为空时，首次写入才允许创建密钥；这样可避免新密钥覆盖旧密文的解密路径。遇到密钥警告时不要卸载应用或清除应用数据。
- 本地数据检查只验证 SQLite 结构及密钥 alias 是否存在；alias 存在不代表每条加密记录均可解密。检查异常时应用不会自动清空、重建或尝试修复数据库。
- SQLite 中时间戳和记录类型未加密；若需要隐藏全部数据库元数据，需要另行评估 SQLCipher 整库加密迁移，并设计数据迁移/回滚方案。
- `allowBackup=false` 禁止 Android 自动备份应用数据，但不能防止获得设备高权限的人访问系统级存储。
- 通知关闭、静音、无预览、内容折叠、通知未送达或系统未提供正文时，应用无法恢复缺失内容。
- 本应用不保证抓取附件原文件、完整媒体内容、微信私有数据库内容或离线期间未交付的通知。
- 设备锁保护依赖 Android 系统设备凭据；它不是独立密码库，也不替代系统锁屏和设备加密。
- 压缩只应用于新写入的记录；旧记录不会在每次启动时批量重写，以免产生一次性 CPU 峰值和数据迁移风险。
- 不包含云同步或远程控制。正式 Release 签名发布工作流已提供，但必须由仓库所有者配置有效签名 Secrets 后，推送匹配版本标签才能实际产出并发布签名 APK。
- 备份提醒目前为应用内提醒：需要打开应用才会检查，不属于后台定时通知。

## 验证范围

JUnit 测试覆盖备份加解密、错误密码、随机盐/随机 nonce、格式头校验、篡改检测、中英文撤回提示及误判边界、候选来源/会话/时间窗口约束、通知消息文本拼接，以及压缩/解压和解压上限。Android Keystore、SQLite VACUUM、NotificationListenerService、设备凭据提示、厂商后台策略及 UI 交互仍需在真实 Android 设备上验收。
